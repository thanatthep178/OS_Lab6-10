ข้อ 1 — บทบาทของระบบปฏิบัติการ
ตอบ
- File System & Permissions: os.path.exists(dataset_path) ตรวจว่าไฟล์มีอยู่ และ open(dataset_path, "rb") ทดลองเปิดอ่านจริง งาน D 
ล้มเหลวเพราะไม่พบ secret_keys.txt จึงยังไม่ได้รับ RAM หรือ GPU ผลนี้แสดงกรณีไฟล์ไม่มีอยู่ ไม่ใช่กรณีถูกปฏิเสธสิทธิ์

- Memory Management: ลูป while ตรวจ RAM ที่เหลือก่อนจัดสรร หากไม่พอ งานจะรอ ส่วน state_lock ป้องกันหลาย Thread แก้ยอด RAM พร้อมกัน 
แนวทางนี้จำลองการจำกัดการใช้หน่วยความจำเพื่อหลีกเลี่ยงภาระเกินความจุ แต่ไม่ได้ทดลอง Thrashing จริง และชุดงานนี้ใช้รวมเพียง 58 GB จึงมี RAM เพียงพอ

- Concurrency & Deadlocks: sorted(req_gpus) ทำให้ทุกงานขอล็อก GPU ตามหมายเลขจากน้อยไปมากเหมือนกัน ช่วยตัดเงื่อนไข Circular Wait ระหว่าง GPU locks 
และคืนทรัพยากรใน finally เมื่อจบงาน


ข้อ 2 — การใช้ทรัพยากรให้เกิดประโยชน์
ตอบ A ใช้ RAM 40 GB และ GPU 0, 1, 2 ส่วน B ใช้ RAM 16 GB โดยไม่ใช้ GPU และ C ใช้ RAM 2 GB กับ GPU 3 ทั้งสามงานจึงทำงานพร้อมกันได้ เพราะใช้ RAM รวม 58 GB ซึ่งไม่เกิน 64 GB 
    และไม่มีการแย่ง GPU ตัวเดียวกัน เมื่อแต่ละงานเสร็จ ระบบคืนทรัพยากรจน RAM กลับเป็น 64 GB และ GPU ทุกตัวว่าง ทั้งหมดเป็นทรัพยากรจำลอง ไม่ใช่การฝึกโมเดลบน GPU จริง

ข้อ 3 — การประยุกต์กับงาน MLOps
ตอบ ความเข้าใจระบบปฏิบัติการช่วยให้ฉันวางแผนรันงาน AI หลายงานได้เหมาะสม ทั้งการจัดคิวงาน การควบคุมการใช้ RAM และข้อจำกัดของ Virtual Memory การป้องกัน Deadlock และการกำหนดสิทธิ์ไฟล์โมเดล 
    ความรู้เหล่านี้ช่วยวิเคราะห์สาเหตุที่งานช้า รอทรัพยากร หรือเข้าถึงไฟล์ไม่ได้ และช่วยออกแบบระบบฝึกกับให้บริการโมเดลให้มีเสถียรภาพมากขึ้น
